## Claim verdicts (validation Appendix A)

- **`C-04` — confirmed with one exception.** Of the sixteen gate kinds listed
  in validation §2, fifteen are enforced in AWCMS CI (job `ci.yml:quality`,
  also `release.yml:validate`). **Migration immutability has no CI gate** in the
  inventory; AWCMS keeps ledger checksums (`frozen/live/migration-ledger.csv`),
  but no check enforcing immutability was found in workflows, package scripts
  or `scripts/`. This is not material for AWBMS, which requires the property
  itself through `AD-25` and `VG-10`. The four advisory entries are operational
  scripts (blog cutover verification, release verification, coverage), not
  gates claimed by `C-04`.
- **`C-05` — confirmed in its load-bearing part.** The consequence the
  validation hangs on `C-05` is that the gates are enforced, not aspirational;
  that is now evidenced. The historical claim that each gate was created in
  response to a production or review failure is not machine-verifiable and is
  not relied on.
- **`C-07` — confirmed, narrowly.** Newsletter subscribe is limited per client
  IP (`newsletter:subscribe:${clientIp}`, default 5 per 300 s) and, separately,
  re-sending a confirmation to the same normalised recipient is suppressed by a
  cooldown (`NEWSLETTER_CONFIRMATION_COOLDOWN_SEC`, default 900 s) with a
  neutral response. Confirm and unsubscribe are per-IP only, and
  `password/forgot` has no recipient dimension in the inventoried code.

## Findings recorded for later stages

From `rate-limits.json` and `credential-formats.json` (facts about AWCMS, not
defects in AWBMS):

- four public auth endpoints read limits through an unvalidated
  `Number(env ?? default)`, so a non-numeric value disables the limit;
- the shared limiter fails open when Redis is configured but a command fails;
- `awcms_push_subscriptions.auth_secret` is stored without encryption and
  without a comment saying that is intended;
- session token hashes (`sha256:`) have no database `CHECK`, while machine
  credential hashes (`mc-sha256:`) do.

These are requirements input for the AWBMS identity and abuse-control design
(issues #13, #14), to be handled after gate 9.
