# ADR-NNNN — Short imperative title

| Field | Value |
|---|---|
| Status | Proposed |
| Date | YYYY-MM-DD |
| Deciders | *names or roles* |
| Supersedes | *ADR-NNNN, or none* |
| Superseded by | *none* |
| Related registers | *`AD-nn`, `OD-nn`, `VG-nn`, or none* |

## Context

What forced a decision. State the problem, the constraints that are real, and
the evidence available. Label the epistemic status of anything uncertain, using
the validation's vocabulary: `[F]` verified fact, `[C]` recorded external
claim, `[A]` assumption.

Say explicitly what is **not** known. An ADR that hides its uncertainty cannot
be re-evaluated later when the uncertainty resolves.

## Decision

One paragraph, in the active voice, stating what will be done. Use RFC 2119
keywords only where the obligation is genuinely normative.

## Alternatives considered

| Alternative | Why not chosen |
|---|---|
| | |

An ADR with no alternatives is a description, not a decision. If there really
was only one option, say why the space was that constrained.

## Consequences

### Accepted costs

What gets harder, slower, or more expensive. Be specific — this is the section
a future reader checks when the decision starts to hurt.

### Benefits

What gets easier.

### Follow-on work

What this decision obliges someone to do next, and who.

## Verification

How anyone can check this decision is actually in force — the command, the
test, the gate. A decision with no observable consequence cannot be verified
and probably should not be an ADR.

## Revisit when

The concrete trigger that should reopen this decision: a measurement crossing a
threshold, an assumption falsified, a dependency reaching end of life. "When it
becomes a problem" is not a trigger.
